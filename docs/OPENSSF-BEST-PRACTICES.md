# OpenSSF Best Practices Evidence

This repository is prepared for the OpenSSF Best Practices passing-badge assessment. The badge application requires a
maintainer to create and attest the project record; repository automation cannot perform that account-level step.

## Enrollment

1. Sign in at <https://www.bestpractices.dev/en/projects/new> with the maintainer GitHub account.
2. Register `https://github.com/gabisonia/PdfiumRaster` as the project repository.
3. Complete the passing-level questionnaire and link the evidence below.
4. Add the badge Markdown generated by the application to `README.md` within 48 hours of earning the badge.

Creating an in-progress project record makes the OpenSSF Scorecard CII-Best-Practices check discover the assessment.
The Scorecard check awards more credit when the passing, silver, or gold level is completed.

## Maintainer Attestations

Some criteria cannot be inferred from repository files. The maintainer must answer them truthfully in the badge
application, including recent response times, the status of any undisclosed or unresolved vulnerabilities, secure
development knowledge, and whether cryptography-related criteria are not applicable to this rendering-only library.

Random hostile PDFs must be fuzzed only in a supervised worker process with time, memory, and crash limits. The normal
test host intentionally limits property-based testing to managed invariants so a native PDFium crash cannot abort the
complete test run.
